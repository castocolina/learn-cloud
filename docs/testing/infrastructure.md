```
src/test/
├── helpers/                    # Shared test utilities
│   ├── test-setup.ts          # TestSetup classes for isolation
│   └── test-utils.ts          # Utility functions (generateConfigId, etc.)
├── components/                # Component unit tests
│   ├── navigation/
│   ├── shared/
│   └── content/
├── lib/                       # Library unit tests
│   ├── services/
│   └── utils/
├── scripts/                   # Script unit tests
├── stores/                    # Store unit tests
├── utils/                     # Utility unit tests
└── e2e/                       # End-to-end tests
    └── *.spec.ts-snapshots/   # Playwright snapshots (git-tracked)
```

### Temporary Files Structure

```
tmp/
└── test/
    ├── unit/                  # Unit test temporary files
    │   ├── scripts/          # Generated by script tests
    │   │   └── {name}-{timestamp}/
    │   ├── services/         # Generated by service tests
    │   └── utils/            # Generated by utility tests
    └── e2e/                   # E2E test temporary files
        ├── *.png             # Debug screenshots (NOT in git)
        ├── playwright-report/
        └── test-results/
```

**Critical**: Files in `tmp/` are **NOT** tracked in git (see `.gitignore`). Never rely on them persisting across sessions.

## Test Environment Configuration

### Vitest Projects Architecture

The project uses **Vitest 4.0+ project-based configuration** with two separate test environments configured in `vitest.config.ts`:

#### 1. Browser Components (`jsdom` environment)

**Purpose**: Tests that need browser APIs (DOM, window, localStorage, etc.)

**Configured patterns**:

```typescript
include: [
	"**/components/**/*.test.ts", // All Svelte components
	"**/layout/**/*.test.ts", // Layout components
	"**/routes/**/*.test.ts", // Route components
	"**/lib/stores/**/*.test.ts", // Svelte stores
	"**/lib/hooks/**/*.test.ts", // Svelte hooks
	"**/utils/hashRouter.test.ts", // Router utility
	"**/lib/utils/template-generator.test.ts" // Template generator
];
```

**Available APIs**:

- `document`, `window`, `navigator`
- `localStorage`, `sessionStorage`
- DOM manipulation (`createElement`, `querySelector`, etc.)
- Svelte component mounting and testing

#### 2. Node Scripts (`node` environment)

**Purpose**: Pure Node.js tests (scripts, services, utilities)

**Configured patterns**:

```typescript
include: [
	"**/scripts/**/*.test.ts", // Build scripts, generators
	"**/lib/services/**/*.test.ts", // Business logic services
	"**/schemas-external.test.ts" // Schema validation
];
```

**Available APIs**:

- File system (`fs`, `path`)
- Node.js modules (`crypto`, `os`, `process`)
- External validation tools (AJV, etc.)

### Where to Place New Tests

**Decision Tree**:

```
Does your test need browser APIs?
├─ YES (DOM, window, localStorage)
│  └─ Place in: src/test/components/, src/test/layout/, or src/test/utils/
│     Environment: jsdom (browser-components)
│
└─ NO (pure Node.js, file operations, CLI)
   └─ Place in: src/test/scripts/ or src/test/lib/services/
      Environment: node (node-scripts)
```

### Adding New Test Locations

If you create tests in a **new directory**, you must update `vitest.config.ts`:

**Example: Adding integration tests**

```typescript
// vitest.config.ts
{
  extends: true,
  test: {
    name: "node-scripts",
    environment: "node",
    include: [
      "**/scripts/**/*.test.ts",
      "**/lib/services/**/*.test.ts",
      "**/schemas-external.test.ts",
      "**/integrations/**/*.test.ts"  // ✅ ADD NEW PATTERN HERE
    ],
    exclude: ["node_modules/", "dist/", ".svelte-kit/", "tmp/", "src/test/e2e/**"]
  }
}
```

### Common Environment Errors

#### ❌ Error: `document is not defined`

**Cause**: Test is in `node` environment but tries to use browser APIs.

**Solution**: Move test to a location covered by `browser-components` pattern, or add the pattern to `vitest.config.ts`.

```typescript
// ❌ BAD: In src/test/scripts/ (node environment)
test("should render component", () => {
	const div = document.createElement("div"); // ERROR: document is not defined
});

// ✅ GOOD: Move to src/test/components/ (jsdom environment)
// Or add pattern to browser-components in vitest.config.ts
```

#### ❌ Error: `Cannot find module 'fs'`

**Cause**: Test is in `jsdom` environment but tries to use Node.js modules.

**Solution**: Move test to a location covered by `node-scripts` pattern.

```typescript
// ❌ BAD: In src/test/components/ (jsdom environment)
import { readFileSync } from "fs"; // May work but NOT IDEAL

// ✅ GOOD: Move to src/test/scripts/ or src/test/lib/services/
```

#### ⚠️ Warning: Test not running

**Cause**: Test file doesn't match any `include` pattern in `vitest.config.ts`.

**Solution**: Add the pattern to the appropriate project configuration.

```bash
# If you create:
src/test/api/endpoints.test.ts

# And it doesn't run, check vitest.config.ts:
# - Is "**/api/**/*.test.ts" in any include array?
# - If not, add it to the appropriate project
```

### Override Environment (Per-File)

You can override the environment for specific files using a comment directive:

```typescript
/**
 * @vitest-environment jsdom
 */
import { test } from "vitest";

// This test will run in jsdom even if the file location
// would normally use node environment
```

**Use sparingly**: It's better to organize files by environment and use `vitest.config.ts` patterns.

### Verifying Environment Configuration

```bash
# Run tests with verbose output to see which environment is used
pnpm run test --reporter=verbose

# Output shows:
#  ✓ browser-components (12)
#  ✓ node-scripts (482)
```

## Common Patterns

### Pattern 1: Script Test with Asset Generation

```typescript
import { ExtendedTestSetup } from "../helpers/test-setup.js";
import { generateConfigId } from "../helpers/test-utils.js";

class ScriptTestSetup extends ExtendedTestSetup {
	public configId: string;
	public outputPath: string;

	constructor(testSuiteId: string = "main") {
		super("scripts", `my-script-${testSuiteId}`);
		this.configId = generateConfigId("test-script", testSuiteId);
		this.outputPath = join(this.tempDir, "output.json");
	}

	setup(): void {
		// Create test directory
		if (!existsSync(this.tempDir)) {
			mkdirSync(this.tempDir, { recursive: true });
		}
	}
}

describe("Script Tests", () => {
	let testSetup: ScriptTestSetup;

	beforeEach(() => {
		testSetup = new ScriptTestSetup("unique-id");
		testSetup.setup();
	});

	it("generates output file", () => {
		runScript({ outputPath: testSetup.outputPath });
		expect(existsSync(testSetup.outputPath)).toBe(true);
	});

	afterEach((context) => {
		testSetup.cleanupIfPassed(context);
	});
});
```

### Pattern 2: Settings Override for Test Performance

```typescript
class FastTestSetup extends ExtendedTestSetup {
	createTestSettings() {
		return {
			...SETTINGS,
			scripts: {
				...SETTINGS.scripts,
				validation: {
					runAfterGeneration: false // Disable slow validation
				}
			}
		};
	}
}

it("runs without validation", () => {
	const settings = testSetup.createTestSettings();
	runScriptWithSettings(settings); // Fast execution
});
```

### Pattern 3: E2E Test with Snapshot

```typescript
import { test, expect } from "@playwright/test";

test.describe("Icon Grid Visual Tests", () => {
	test("default state matches snapshot", async ({ page }) => {
		await page.goto("/showcase/icon-grid");
		await page.waitForLoadState("networkidle");

		const iconGrid = page.locator("[data-testid='icon-grid']");
		await expect(iconGrid).toHaveScreenshot("icon-grid-default.png");
	});
});
```

### Pattern 4: Conditional Cleanup Debugging

```typescript
afterEach((context) => {
	testSetup.cleanupIfPassed(context);

	// If test failed, files are preserved
	if (context.task.result?.state !== "pass") {
		console.log(`Test failed - artifacts preserved in: ${testSetup.tempDir}`);
	}
});
```

### Pattern 5: Validation Tests with Immediate Cleanup

For tests that create their own TestSetup instances inside the test body (common for validation/integration tests):

```typescript
it("should validate with TypeScript compiler", async () => {
	// Create isolated setup for this specific test
	const validationSetup = new TestSetupWithValidation("ts-validation");
	await validationSetup.setup();

	const generator = validationSetup.createGenerator();
	const success = await generator.generate();

	expect(success).toBe(true);
	expect(existsSync(validationSetup.outputPath)).toBe(true);

	// Test passed - cleanup immediately
	// Cannot use cleanupIfPassed() here because we're inside test body
	validationSetup.forceCleanup();
});
```

**When to use this pattern**:

- Tests that need custom TestSetup instances per test
- Validation/integration tests with special configuration
- Tests where setup cannot be shared via `beforeEach`

**Key difference**: Use `forceCleanup()` instead of `cleanupIfPassed()` when cleanup happens inside test body.
